# СКиП 4.9.2 Safety + Offline (кандидат для испытаний)

**Основа:** пользовательский архив `SKiP_v4.9.1_Offline_GitHub_Pages.zip`.
**Дата:** 17 ноября 2026 г.
**Развёртывание:** статические файлы в корень репозитория GitHub Pages. Backend не нужен.

## Критические исправления

1. **F01: IndexedDB стала источником истины.** При старте и при разблокировке читается `primary/current` из `skipp_recovery_v1`, а не зеркало `skipp_offline_v2` в localStorage. Если зеркало не удаётся обновить, свежая ревизия остаётся основной. Сохраняется compare-and-swap между вкладками.
2. **F02: удаление столбцов.** При удалении столбца карточки явно перемещаются в корзину после подтверждения; при редактировании сохранены ранее существовавшие скрытые поля карточек.
3. **F03: отказ записи.** Обработчики форм ожидают итог асинхронного сохранения и не закрывают форму при сбое. Есть откат оптимистического состояния.
4. **F04: аварийная выгрузка.** При режиме только чтения можно скачать пакет с исходной записью базы и снимком. Это **аварийный образ**, не обычный файл импорта. Нельзя раскрывать старые незашифрованные снимки с заблокированного экрана PIN. Импорт стандартного файла при режиме чтения выполняет предварительное сохранение исходной версии в recovery store.
5. **F05/F08: валидация.** Проверка допустимых типов, дублей ID и цветов статусов; escape ID в HTML-атрибутах; проверка структуры до сохранения. Неподходящий исходный архив не удаляется автоматически.
6. **F06: переход на PIN.** Основная запись и локальный previous-снимок переводятся в зашифрованный формат в одной IndexedDB-транзакции. Для обнаруженных конфликтных plaintext-копий предусмотрена защита с отдельным сохранением зашифрованного образа.
7. **F07/F09/F13:** блокировка экрана не отменяется при сбое хранения; автоархивация применяет правки через контролируемый commit; ограничена история undo и первоначальный рендер основных списков.
8. **F17:** исправлено удержание обработчика клавиатуры после PIN, резервный HUD больше не закрыт слоем загрузки.

## Офлайн-функции 4.9.1 сохранены и усилены

- Все четыре MP4, саундтрек, четыре голоса, изображения/темы из 4.9.1 включены **без изменений байтов**.
- Версия кэша: `v492-safety-1`, префикс включает scope текущего GitHub Pages. Чужие scope-кэши не очищаются.
- Минимальная оболочка HTML/JS/CSS устанавливается согласованно; медиа сохраняются отдельно, отказ необязательного файла не отменяет установку PWA.
- Загрузка и навигация используют готовый кэш без ожидания зависшей сети. HTTP Range для MP4 остаётся нативным; офлайн-показ MP4 использует Blob URL из Cache Storage.
- Обязательные медиа для сообщения о готовности: обе версии 720p, музыка, HUD/постеры и две theme-картинки; HD и голоса отображаются как дополнительные.
- Обновление нового Service Worker не захватывает работающую сессию принудительно; обычно для перехода потребуется закрыть все окна старого приложения и открыть заново.

## Нельзя считать исправленным или проверенным

- В **реальном iPad Safari/PWA** не проводились E2E-проверки сохранения, восстановления, PIN, первого офлайн-запуска, воспроизведения голоса/музыки и обновления между версиями. Не объявлять стабильным без этих испытаний.
- Алгоритм короткого PIN и тревожное обнуление не переработаны. Не проводилось изменение правил запуска заставки.
- Дизайн четырёх новых тем 4.9.1 не переделан: замечания о полях/обрезании остаются открытыми.
- Время и синхронизация музыки/голоса на iPad ещё требуют тестов. Имеются открытые замечания F16/F18/F20/F22.
- Совместное использование IndexedDB/localStorage приложениями **одного origin** не изолировано новой схемой хранения; изменение имён без миграции опасно.
- Не исправлялся Android APK-workflow из отдельного репозитория (F14). Эта поставка предназначена только для GitHub Pages.
- Доступность сверх больших баз (5–30 тысяч), аварийная миграция и операции с экзотическими старыми JSON требуют дополнительного тестирования.

## Установка и план испытаний

1. **Перед обновлением:** в текущем рабочем приложении выполните «Настройки → Данные → Выгрузить данные», сохраните отдельный JSON-файл в приложении «Файлы» и убедитесь, что файл действительно появился. Рекомендуется шифрование длинным паролем.
2. Вначале испытайте ZIP на **отдельной тестовой копии** или резервном устройстве/профиле. Не очищайте Safari, не удаляйте установленную PWA с единственной рабочей базой.
3. Скопируйте **содержимое** ZIP (не ZIP как один файл) в корень GitHub Pages. Дождитесь публикации; с интернетом полностью завершите старое PWA и откройте заново. В «Настройки → Оформление → Автономная работа» нажмите «Проверить и скачать», дождитесь подтверждения.
4. С тестовой базой проверьте: сохранение и повторный вход; удаление столбца и восстановление карточек из корзины; экспорт/импорт; смену PIN; блокировку при ошибках сети; авиарежим; звук и видео; обновление с открытым редактором.
5. Для версии на основном iPad после обновления внимательно проверьте **количество и содержимое задач** до создания новых записей. Если что-то не совпадает, не редактируйте данные и воспользуйтесь отдельным резервным JSON-файлом.

**Обратите внимание:** локальный IndexedDB, Cache Storage и localStorage зависят от политики хранения iPadOS. Кэш не заменяет независимо сохранённую резервную копию.
